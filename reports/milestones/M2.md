# M2 workload checkpoint

Implemented fixed-sample replay benchmark in workload.py, CLI benchmark --replay,
and interface accounting test. Commands (virtual-environment Python):
```
python -m qec_project benchmark --replay results/f2efb42957014d81b49d07cfb8c63411/2
python -m pytest --basetemp=results/m2-tests-2 -q
```
TMP/TEMP must point to results in the restricted app, as in M1. Timings warm up
100 shots then measure ten full batches and 1000 separate decode calls.
Setup includes DEM file loading. No process memory/CPU-utilization probe was used;
array payload size is recorded and is not total process memory.

Measured X d=3, rounds=3, p=.005, 1000 saved shots: median batch throughput
1,322,926 shots/s; separate single-decode p50/p95/p99=10.3/22.505/48.104 us.
These scopes differ: Python call overhead is amortized in a batch. Timing variation
is substantial on this shared laptop; these are preliminary, not real-time claims.

Wire format: uint64 window ID, uint32 ending round, uint32 payload count, dense
byte-packed detector bits OR uint32 sparse indices, plus byte-rounded logical frame.
Same headers/frame in both formats, without compression. Dense=20 bytes/window;
sparse mean=22.532 bytes/window. Sparse is worse here: removing events alone does
not prove bandwidth savings. NumPy bool arrays are not the wire encoding.

Evidence: reports/evidence/M2/workload.json and event_density.png. Environment is
recorded in M1's parent manifest; CPU model/frequency are not established, so do
not generalize timing to other machines. Next: M3 conservative predecoder.
