# M5 — fixed-graph RTL prototype

## Purpose and architecture

Test whether the conservative Python rule can be expressed as synthesizable
digital logic, not whether it already beats software on physical hardware.
Generated graph-specialized SystemVerilog computes isolated active pairs in
parallel and XORs their detector support and observable mask. A one-entry elastic
output buffer implements bounded valid/ready storage. Synchronous reset flushes
that entry. See rtl/README.md for the interface and reset replay responsibility.
Unsupported local mechanisms remain for MWPM; no errors are silently discarded.

Before translation, expanded Python tests check reconstruction and disjoint
choices across every 0/1/2/3-event syndrome of d=3 X/Z circuits, plus a synthetic
two-observable mask cancellation case. These checks establish algebraic
consistency, not optimal decoding or a physical-fault correctness proof.

## Actual validation

Windows Python 3.12.14, Stim 1.16.0, PyMatching 2.4.0, NumPy 2.5.4.
Ubuntu Python 3.14.4, cocotb 2.1.0, Verilator 5.032, Yosys 0.52.
30 Python tests passed. Three cocotb scoreboard runs passed with no failures.

| Case | Detectors | Golden vectors | Generic cells | Register bits |
|---|---:|---:|---:|---:|
| X, d=3, rounds=3 | 24 | 2302 | 602 | 25 |
| Z, d=3, rounds=3 | 24 | 2302 | 597 | 25 |
| X, d=5, rounds=5 | 120 | 9262 | 7055 | 121 |

Golden vectors include zero/all events, all single detectors and detector pairs,
1000 Stim windows and 1000 random dense windows. Scoreboard checks full residual
and frame, uninterrupted traffic, bubbles, backpressure, simultaneous transfer,
and three reset edges. Two pending outputs are deliberately flushed by resets;
the consumed/accepted difference is accounted for. No mismatch was observed.
Unstalled input-to-output availability is one cycle, initiation interval one
cycle. Stalled test cycle counts are recorded in cycles.json, not a throughput
benchmark. 10 ns is a testbench clock period only, without timing closure.

## Commands actually run

Windows project virtual-environment Python:
```
python -m pytest --basetemp=results/rtl-reference-tests -q
python scripts/prepare_rtl.py --output results/rtl-x3
python scripts/prepare_rtl.py --basis Z --output results/rtl-z3
python scripts/prepare_rtl.py --distance 5 --output results/rtl-x5
python scripts/collect_rtl_evidence.py
python scripts/plot_rtl.py
```
TMP/TEMP pointed to results for Python tests as documented in earlier reports.
Ubuntu:
```
python3 -m venv /tmp/qec-rtl-env
/tmp/qec-rtl-env/bin/python -m pip install cocotb==2.1.0
/tmp/qec-rtl-env/bin/python scripts/verify_rtl.py results/rtl-x3
/tmp/qec-rtl-env/bin/python scripts/verify_rtl.py results/rtl-z3
/tmp/qec-rtl-env/bin/python scripts/verify_rtl.py results/rtl-x5 --build-dir /tmp/qec-rtl-x5-build
```
The initial project-local Linux environment installation was much slower on the
Windows-backed filesystem. The first launch before cocotb installation finished
failed with a missing-module error. A minimal native temporary environment resolved
that launch issue; using native build storage improved compilation turnaround.
The temporary environment must be recreated if removed/restarted.
Its exact package versions are saved in requirements-rtl-lock.txt. The redundant
slow full Linux dependency installation was stopped after verification completed;
the partially populated .venv-wsl is not the validated execution environment.
Use a fresh Linux-native environment and the RTL lock for reproducibility.

## Artifacts and interpretation

Generator, verification runner, collector and chart script in scripts/;
testbench and interface documentation in rtl/; Python invariant tests in tests/.
reports/evidence/M5 stores generated SV, DEM, metadata/hash, XML test results,
cycle records, synthesis logs, summary and generic-cell chart. Large build products
and vector files stay in ignored results/ and can be regenerated.

No physical FPGA, target-specific mapping, frequency, power or end-to-end hardware
speedup was measured. Fixed graph and full-window parallel input are limitations.
No deep FIFO, serial link or real-time controller is included. Larger distances,
both bases at each size, multiple observable RTL, formal equivalence and timing
closure remain extensions. The prototype is verified on the listed supported
graphs and vectors; this is not exhaustive proof of all possible inputs.
